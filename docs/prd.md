# PRD: PDF 요약 웹 앱

> 표기 규칙
> - **[결정]**: 사용자와 질문을 주고받아 확정한 내용
> - **[가정]**: PM이 임시로 정한 값. 사용자 확인이 필요하다.
> - **[열린 질문]**: 설계 단계 또는 사용자 확인에서 정할 사항

## 1. 개요

### 1.1 제품 한 줄 설명
PDF 문서를 올리면 AI가 핵심 내용을 한국어로 요약해 보여 주는 웹 앱.

### 1.2 배경
대학생은 강의 자료와 논문(특히 영어 원문)을 많이 읽어야 하는데, 전체를 읽기 전에 핵심을 빨리 파악하기가 어렵다. 이 앱은 PDF를 끌어다 놓기만 하면 한국어 요약을 바로 보여 줘서 시험 공부와 과제 준비 시간을 줄여 준다.

### 1.3 기술 언급 범위
이 문서는 "AI 모델을 호출해 요약한다" 수준까지만 다룬다. 아키텍처, API, 데이터 저장 방식, 기술 스택 같은 구현 방식은 다음 단계(설계)에서 정한다.

## 2. 대상 사용자와 사용 상황

**[결정]** 대학생이 강의 자료나 논문 PDF를 올려서 핵심 내용을 빨리 파악하고, 시험 공부나 과제 준비에 쓴다.

### 2.1 페르소나
- 이름(가상): 민지, 대학교 3학년
- 상황: 영어 전공 논문과 교수님 강의 PDF를 매주 읽어야 한다.
- 어려움: 영어 논문 한 편을 다 읽기 전에 읽을 가치가 있는지, 핵심이 무엇인지 알고 싶다.

### 2.2 사용 시나리오
1. **시험 전날 강의 자료 훑기:** 민지는 50쪽짜리 강의 PDF를 화면에 끌어다 놓는다. 한 줄 요약, 핵심 개념, 중요한 정의와 공식을 보고 공부 순서를 정한다.
2. **영어 논문 파악:** 과제용 영어 논문 PDF를 올린다. 요약이 한국어로 나와서, 본문을 읽기 전에 논문의 주제와 핵심 개념을 이해한다.

## 3. 목표와 비목표

### 3.1 목표
- 글자가 있는 PDF를 올리면 한국어 요약(한 줄 요약, 핵심 개념, 정의/공식)을 보여 준다.
- 회원가입 없이 바로 쓸 수 있다.
- 잘못된 파일을 올렸을 때 이유를 알려 준다.

### 3.2 비목표
- 문서와 대화하는 기능, 여러 문서 일괄 처리, 계정 기반 서비스는 이번 버전의 목표가 아니다. (6장 참고)

## 4. 기능 요구사항

우선순위: **필수** / 있으면 좋음 / 향후 검토

| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| FR-1 | PDF 끌어다 놓기 업로드 | 사용자가 PDF 파일을 화면의 업로드 영역에 끌어다 놓아 올린다. **[결정]** | 필수 |
| FR-2 | 파일 선택 버튼 | 끌어다 놓기의 보조 수단으로, 버튼을 눌러 파일을 고를 수 있다. FR-1 업로드 기능에 포함한다. **[가정]** | 필수 |
| FR-3 | AI 요약 생성 | 올린 PDF의 글자를 AI 모델에 보내 요약을 만든다. 구현 방식은 설계 단계에서 정한다. | 필수 |
| FR-4 | 한국어 요약 출력 | 원문이 영어여도 요약은 한국어로 보여 준다. **[결정]** | 필수 |
| FR-5 | 요약 화면 표시 | 5장의 구성대로 결과를 보여 준다. **[결정]** | 필수 |
| FR-6 | 오류 안내 | 7장의 경우마다 이유를 알려 주는 문구를 보여 준다. **[결정]** | 필수 |
| FR-7 | 파일 크기 제한 적용 | 8.1절의 제한을 넘으면 업로드를 거절하고 안내한다. **[가정]** | 필수 |

### 4.1 이번에 하지 않음 / 향후 검토
사용자가 이번 버전 기능으로 선택하지 않은 항목이다.

| 항목 | 분류 |
|------|------|
| 요약 결과 복사·다운로드 | 향후 검토 |
| 요약 길이 선택 | 향후 검토 |
| 요약 기록 보기 | 향후 검토 |
| 진행 상태 표시와 실패 시 재시도 | 향후 검토 (완료 기준에서 제외됨. 단, 처리 중임을 알리는 최소한의 표시는 설계 단계에서 판단) |
| 응답 시간 목표 | 향후 검토 (이번 버전은 목표를 정하지 않음) |

## 5. 요약 화면 구성

**[결정]** 요약 화면에는 다음을 순서대로 담는다.

1. **한 줄 요약:** 문서 전체를 한 문장으로 설명한다.
2. **핵심 개념 3~5개:** 개념 이름과 짧은 설명.
3. **중요한 정의나 공식:** 문서에 나오는 주요 정의와 공식.
4. 원문이 영어여도 위 내용은 모두 **한국어**로 표시한다.

## 6. 이번 버전에서 제외하는 기능

**[결정]** 아래 기능은 이번 버전에서 뺀다.

| 제외 기능 | 이유 |
|-----------|------|
| 회원가입·로그인 | 첫 버전은 바로 써 보는 경험에 집중하고, 계정 관리 부담을 없앤다. |
| 문서에 질문하기(채팅) | 요약 품질을 먼저 검증하는 것이 우선이다. |
| 스캔 PDF 글자 인식(OCR) | 글자가 있는 PDF만 지원해 범위를 줄인다. 스캔 PDF는 안내 문구로 알린다. |
| 여러 PDF 한꺼번에 요약 | 한 번에 문서 하나만 처리해 단순하게 시작한다. |

## 7. 오류 처리 요구사항

**[결정]** 다음 세 경우는 각각 이유를 알려 주는 안내 문구를 보여 준다.

| ID | 상황 | 안내 내용(요지) |
|----|------|-----------------|
| ER-1 | PDF가 아닌 파일을 올림 | PDF 파일만 올릴 수 있다는 안내 |
| ER-2 | 용량 또는 쪽수 초과 | 어떤 제한(용량/쪽수)을 넘었는지와 허용 한도 안내 |
| ER-3 | 글자가 없는 스캔 PDF | 글자를 읽을 수 없는 PDF라 요약할 수 없다는 안내 |

정확한 문구는 설계/구현 단계에서 정한다.

## 8. 가정, 제약, 열린 질문

### 8.1 파일 크기 제한
**[결정]** (설계 단계에서 확정, 처음 PM 가정 20MB·100쪽을 대체)
- 용량: 최대 **4MB**
- 쪽수: 제한 없음
- 근거: 배포 환경(Vercel)의 요청 크기 한도 약 4.5MB 안에 들어가야 한다. 자세한 내용은 [설계 문서](superpowers/specs/2026-11-25-pdf-summary-design.md) 참고.

### 8.2 기타 가정
- **[가정]** 한 번에 PDF 한 개만 올린다. (여러 개 동시 요약 제외 결정에서 도출)
- **[가정]** 요약은 글자가 들어 있는 PDF만 대상으로 한다. (OCR 제외 결정에서 도출)
- **[가정]** 사용자는 인터넷에 연결된 웹 브라우저로 접속한다. 모바일 지원 범위는 정하지 않았다.

### 8.3 열린 질문 (설계 단계 또는 사용자 확인)
1. 정의나 공식이 없는 문서일 때 해당 영역을 어떻게 표시할 것인가? (숨김 또는 "없음" 문구)
2. 요약 결과와 업로드한 PDF를 보관할 것인가? 보관한다면 얼마나 오래, 개인정보와 저작권 관점에서 어떻게 다룰 것인가?
3. ~~8.1의 용량·쪽수 제안값을 그대로 쓸 것인가?~~ → 4MB로 확정(설계 문서)
4. 한국어 문서를 올렸을 때도 같은 형식으로 요약하는가? (지원 언어 범위)
5. 요약 처리 중 사용자에게 무엇을 보여 줄 것인가? (진행 표시는 완료 기준 밖)
6. 공식은 어떤 형태로 보여 줄 것인가? (일반 글자 또는 수식 표기)
7. 요약 AI의 사용 비용 상한과 이용량 제한이 필요한가?
8. 모바일 화면 지원 여부.

## 9. 완료 기준 (검증 가능한 체크리스트)

- [ ] 글자가 있는 PDF를 화면에 끌어다 놓으면 한 줄 요약이 한국어로 표시된다.
- [ ] 같은 결과 화면에 핵심 개념이 3~5개 한국어로 표시된다.
- [ ] 같은 결과 화면에 중요한 정의나 공식이 한국어 설명과 함께 표시된다.
- [ ] PDF가 아닌 파일을 올리면 PDF만 가능하다는 이유가 안내된다.
- [ ] 4MB를 넘는 PDF를 올리면 초과한 이유가 안내된다.
- [ ] 글자 없는 스캔 PDF를 올리면 글자를 읽을 수 없어 요약할 수 없다는 이유가 안내된다.
