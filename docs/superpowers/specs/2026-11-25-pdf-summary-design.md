# 설계: PDF 요약 웹 앱 (summary4pdf-ch7)

- 작성일: 2026-11-25
- 기준 문서: [docs/prd.md](../../prd.md)
- 표기: **[사용자]** 사용자가 정한 것 / **[내 판단]** 대화 중 제안해 사용자가 "이대로 진행"으로 받아들인 기본값 / **[빌더]** 만드는 쪽에서 정할 것

## 1. 목적과 이유

대학생이 강의 자료나 논문 PDF를 올려서 핵심 내용을 빨리 파악하고, 시험 공부나 과제 준비에 쓴다. **[사용자]**
영어 논문도 한국어로 요약해 주어, 본문을 다 읽기 전에 무엇이 중요한지 알 수 있게 하는 것이 핵심 가치다.

## 2. 목표 · 비목표 · 실패 조건

### 목표
- 글자가 있는 PDF 한 개를 끌어다 놓으면 한 줄 요약, 핵심 개념 3~5개, 중요한 정의·공식이 **한국어**로 나온다. **[사용자]**
- 잘못된 입력(PDF 아님, 4MB 초과, 글자 없는 스캔 PDF)은 이유를 알려 준다. **[사용자]**
- 로그인 없이 바로 쓴다. **[사용자]**

### 비목표 (이번 버전에서 하지 않음) **[사용자]**
회원가입·로그인, 문서에 질문하기(채팅), 스캔 PDF 글자 인식(OCR), 여러 PDF 한꺼번에 요약, 요약 복사·다운로드, 요약 길이 선택, 요약 기록, 응답 시간 목표, 수식 기호 렌더링.

### 실패로 보는 경우 (기술적으로 돌아가도)
- 영어 원문의 요약이 영어로 나온다.
- 오류가 났을 때 이유 없이 빈 화면이나 영어 오류 원문이 보인다.
- `OPENROUTER_API_KEY` 값이 브라우저나 깃허브 저장소에 노출된다.
- 사용자가 올린 PDF나 요약이 **우리 서버(앱·DB·파일)**에 저장된다. OpenRouter와 모델 제공사 쪽 보관은 이 조건에 넣지 않는다. **[사용자]**

## 3. 제약

- **프레임워크:** Next.js. **[사용자]** 버전과 라우터 방식(App Router 권장)은 **[빌더]**.
- **배포:** 깃허브 저장소 `summary4pdf-ch7`에 올리고 Vercel에 배포한다. **[사용자]**
  - 현재 깃허브에서 `summary4pdf-ch7`을 조회하면 기존 저장소 `summary4pdf-ch7-v1`(이름이 바뀐 옛 저장소)로 연결된다. `-v1`은 건드리지 않고 **`summary4pdf-ch7` 공개 저장소를 새로 만든다.** 이렇게 하면 옛 이름으로의 연결은 끊긴다. **[내 판단]**
  - Vercel은 **새 프로젝트**를 만든다. **[사용자]** 옛 저장소에 연결된 `summary4pdf-ch7.vercel.app` 배포는 그대로 두므로, 새 앱 주소는 다른 이름이 된다.
  - Vercel 요금제는 **Hobby(무료)**. **[사용자]** 함수 실행 시간 한도와 요청 크기 한도는 Hobby 기준으로 맞추고, 정확한 값은 구현할 때 Vercel 문서로 확인한다.
  - 저장소 생성, 푸시, Vercel 연결은 실제로 하기 전에 사용자에게 다시 확인한다.
- **파일 크기:** PDF는 **4MB까지만** 받는다. **[사용자]** (Vercel 함수 요청 본문 한도 약 4.5MB 안에 들어가는 값.) PRD의 "20MB·100쪽" 가정은 이것으로 대체하고, **쪽수 제한은 두지 않는다.** **[내 판단]**
- **AI 호출:** OpenRouter. **[사용자]**
  1. 먼저 `nvidia/nemotron-3-ultra-550b-a55b:free`를 부른다.
  2. 응답이 없거나(정해진 시간 초과) 오류가 나면 `nvidia/nemotron-3.5-super-vl:free`로 한 번 넘어간다.
  3. 둘 다 실패하면 사용자에게 "잠시 후 다시 시도해 주세요"라고 안내한다. **[내 판단]**
  - 첫 모델의 제한 시간(초)과 재시도 여부는 **[빌더]**. 단, 두 번의 호출이 Vercel Hobby 함수 실행 시간 한도(`maxDuration`) 안에 끝나야 한다.
  - 구현 전에 두 모델 ID가 OpenRouter에 실제로 있는지 확인한다. 없으면 대체 모델을 정하기 전에 사용자에게 묻는다.
  - 무료 모델은 OpenRouter 계정의 개인정보 설정(무료 모델 입력 보관·학습 허용)을 켜야 호출되는 경우가 있다. 이 설정은 **사용자가 직접** 바꾸며, 구현 계획에 "사용자 확인 단계"로 넣는다.
- **사용량 제한:** 별도 장치(IP별 횟수 제한 등)를 두지 않는다. **[사용자]** 무료 모델의 계정 호출 한도(분당·하루)가 차서 두 모델 모두 거절하면, "잠시 후 다시 시도해 주세요" 안내로 처리한다. QA 반복 시험도 같은 한도를 쓰므로 실제 모델 호출 시험은 횟수를 아껴서 하고, 나머지는 모델 응답을 흉내 낸 시험으로 한다. **[내 판단]**
- **API 키:** `.env`의 `OPENROUTER_API_KEY`를 서버 쪽에서만 읽는다. **[사용자]** `.env*` 파일은 열거나 내용을 출력하지 않는다(프로젝트 규칙). Vercel에는 같은 이름의 환경 변수로 등록하며, 값 입력은 사용자가 한다.
- **언어:** 화면 문구, 주석, 문서, 커밋 메시지는 한국어(프로젝트 규칙).
- **저장하지 않음:** 올린 PDF와 요약 결과는 서버·DB·파일 어디에도 저장하지 않는다. 새로고침하면 사라진다. **[내 판단]**

## 4. 화면 (한 페이지) **[내 판단, 사용자 승인]**

1. **처음 화면:** 가운데 큰 업로드 상자. PDF를 끌어다 놓거나 "파일 선택" 버튼으로 올린다. 상자 안에 "PDF, 4MB까지" 안내. 상자 아래에 작은 글씨로 "문서 내용은 요약을 위해 외부 AI 서비스로 보내지고, 이 앱에는 저장되지 않아요" 안내 한 줄. **[사용자 선택에 따른 추가]**
2. **요약 중:** 로딩 표시와 "요약하는 중이에요" 문구. (PRD 완료 기준에는 없지만 멈춘 것처럼 보이지 않게 최소한으로 넣는다.)
3. **결과 화면** (위에서 아래로):
   - 파일 이름
   - **한 줄 요약** — 가장 크고 눈에 띄게
   - **핵심 개념 3~5개** — 개념 이름 + 짧은 설명을 카드로
   - **정의·공식** — 목록. 공식은 일반 글자로 표시(수식 렌더링 없음)
   - 정의·공식이 없으면 칸을 숨기지 않고 "이 문서에서 찾은 정의나 공식이 없어요"
   - 문서가 너무 길어 앞부분만 요약했다면 "앞부분만 요약했어요" 표시
   - "다른 PDF 요약하기" 버튼(처음 화면으로)
4. **휴대폰:** 화면 폭에 맞춰 보인다. 끌어다 놓기 대신 파일 선택으로 올린다.
5. 디자인은 "깔끔하게" **[사용자]**. 색·글꼴·레이아웃 세부는 **[빌더]**(frontend-developer).

## 5. 오류 안내

| 경우 | 안내(요지) | 출처 |
|------|-----------|------|
| PDF가 아닌 파일 | PDF 파일만 올릴 수 있어요 | PRD ER-1 |
| 4MB 초과 | 4MB까지만 올릴 수 있어요 (파일 크기 함께 표시) | PRD ER-2, 한도 변경 |
| 글자 없는 스캔 PDF | 글자를 읽을 수 없는 PDF라 요약할 수 없어요 | PRD ER-3 |
| 두 AI 모델 모두 실패(호출 한도 초과 포함) | 잠시 후 다시 시도해 주세요 | 추가 **[내 판단]** |

- PDF 여부와 4MB 검사는 화면에서 먼저 하고, 서버에서도 다시 한다. **[내 판단]**
- "글자 없음"을 판단하는 기준(추출된 글자 수 기준 등)은 **[빌더]**.
- 정확한 문구는 frontend-developer가 다듬는다.

## 6. 처리 흐름

```
브라우저: PDF 끌어다 놓기 → (PDF 여부·4MB 검사) → 서버로 전송
서버: (다시 검사) → PDF 텍스트 추출 → 글자 없으면 ER-3
     → 텍스트가 모델 입력 한도를 넘으면 앞부분만 사용(잘렸다는 표시 포함)
     → OpenRouter 1차 모델 호출 → 실패/시간 초과 시 2차 모델
     → 응답을 정해진 구조로 해석 → 브라우저로 반환
브라우저: 결과 화면 표시
```

- 요약 결과는 다음 구조로 주고받는다(필드 이름은 **[빌더]**): 한 줄 요약(문자열), 핵심 개념 목록(이름·설명, 3~5개), 정의·공식 목록(0개 이상), 앞부분만 요약했는지 여부.
- 모델에게 한국어로, 위 구조(JSON)로 답하라고 지시한다. 응답이 구조에 맞지 않으면 실패로 보고 다음 모델로 넘어간다. **[내 판단]**
- PDF 텍스트 추출 라이브러리, 모델 입력 한도 값, 프롬프트 문구는 **[빌더]**.

## 7. 역할 분담 **[사용자]**

`.claude/agents`의 에이전트에게 나눠 맡긴다.

| 에이전트 | 맡는 일 |
|---------|--------|
| backend-developer | PDF 업로드 받기(4MB 제한)와 텍스트 추출, 서버 쪽 검사와 오류 응답 |
| ai-integration-specialist | 추출한 텍스트를 OpenRouter로 요약, 1차→2차 모델 대체, 프롬프트, 응답 해석 |
| frontend-developer | 끌어다 놓기 업로드 화면과 요약 결과를 깔끔하게 보여 주는 한국어 화면, 오류·로딩 표시 |
| qa-engineer | 여러 상황에서 시험하고, 문제를 찾으면 담당 에이전트가 고친 뒤 다시 확인. 문제가 없어질 때까지 반복 |

- 순서와 일을 나누는 경계(예: 서버 API 모양을 먼저 정하고 화면과 AI 작업을 나란히 진행)는 구현 계획에서 정한다.
- qa-engineer는 Bash로 시험을 돌릴 수 있지만 파일을 고치는 도구는 없다. 고칠 점은 보고하고, 수정은 해당 담당 에이전트가 한다.

## 8. 완료 기준

PRD 9장을 그대로 쓰되, 한도를 4MB로 바꾼다.

- [ ] 글자가 있는 PDF를 끌어다 놓으면 한 줄 요약이 한국어로 표시된다.
- [ ] 같은 화면에 핵심 개념이 3~5개 한국어로 표시된다.
- [ ] 같은 화면에 중요한 정의나 공식이 한국어 설명과 함께 표시된다(없으면 "없어요" 문구).
- [ ] PDF가 아닌 파일을 올리면 PDF만 가능하다는 이유가 안내된다.
- [ ] 4MB를 넘는 PDF를 올리면 초과한 이유가 안내된다.
- [ ] 글자 없는 스캔 PDF를 올리면 글자를 읽을 수 없어 요약할 수 없다는 이유가 안내된다.

qa-engineer가 시험할 상황(최소): 한국어 강의 PDF, 영어 논문 PDF, 정의·공식이 없는 PDF, 4MB에 가까운 큰 PDF, 4MB 초과 PDF, PDF가 아닌 파일(확장자만 .pdf인 파일 포함), 스캔 PDF, 1차 모델 실패 시 2차 모델로 넘어가는지, 두 모델 모두 실패 시 안내, 휴대폰 폭 화면. 시험용 PDF 준비 방법은 **[빌더]**.

## 9. 만드는 쪽에 맡기는 것 (요약)

Next.js 세부 버전과 구조, PDF 텍스트 추출 라이브러리, 모델 제한 시간·재시도, 모델 입력 한도와 자르는 방식, 프롬프트 문구, 응답 필드 이름, "글자 없음" 판단 기준, 시각 디자인 세부, 시험용 PDF 준비, 자동화 시험 도구 선택.
